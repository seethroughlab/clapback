The exchange

Why plug your tool in

Skip the recompute

A hit is 512 floats. A miss is seconds of CPU and a 600 MB model — minutes per album on a laptop, longer on a Pi. Look up first; run the model only for what nobody has computed.

Similarity across libraries, not one user's

/v1/similar answers in {{ similarity_ms }} ms over every library that has plugged in, and {{ top.named_pct|fmt_pct(0) }} of results carry a MusicBrainz recording id a person can read. The rest are hashes, shown as hashes.

Somewhere to submit to again

beets and Picard shipped exactly this fetch-and-submit pair and lost it when AcousticBrainz closed in 2022. This corpus carries embeddings — reconcilable between contributors — not the estimates that could not be.

The contract

What plugging in takes

  1. Fingerprint the audio and hash it canonically. SHA256 of the AcoustID fingerprint as chromaprint returned it — not as your database stored it.
  2. Produce the vector through a declared pipeline. The reference is clapback-embed; your own pipeline identity is allowed, at 512 dimensions.
  3. Look up before you contribute. A repeat submission is recorded as agreement, and one install agreeing with itself is not evidence.
  4. Send client_id and pipeline_version. A random UUID minted on first contribution; the identity of everything that can move a vector.
row = corpus.lookup(key, pipeline_version)
if row is not None:
    vector = row["embedding"]          # the commons already had it — skip the model
else:
    vector = my_embedder(path)         # your pipeline, declared by pipeline_version
    corpus.contribute(fingerprint_hash=key, embedding=vector,
                      pipeline_version=pipeline_version, client_id=client_id)

Almost every vector here came from one library. The mechanism for finding out whether independent contributors agree is in place ahead of the evidence, on purpose — and a second contributor is the single most valuable thing that could happen to it.

Every row declares the pipeline that produced it and is keyed on a hash any client can reproduce from the audio. The corpus is smaller than it has ever been, and the first version where a disagreement is about the recording rather than about whose code ran.

Four rules

How it keeps its word

One implementation, pinned

Everyone runs clapback-embed. Front-end, windowing, pooling, checkpoint and precision compose into one identity string that travels with every vector.

A hash, never a filename

The corpus receives the SHA256 of a fingerprint and cannot recover a title, an artist or a path. Naming a row is a claim its contributor makes, counted per client.

First vector wins, the rest are measured

A repeat contribution is compared, not overwritten. The same audio on two architectures agrees to 6.6e-11; two rips of one recording differ by 3e-4. That gap is the room agreement has.

Asserted, not proven; reported, not ruled

The server believes the pipeline you declare. No threshold calls a vector trustworthy — you are told how many independent submissions matched, and how closely.
